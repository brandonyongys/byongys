After releasing [AskAuntieBot](t.me/AskAuntieBot), I found issues almost immediately - covered [here](../posts/products-chatbot-mvp1). Over the past few days I fixed most of them. The coverage issue is a separate problem - it needs a dedicated scraper and parser for each supermarket - so that one stays open.

<hr>

::image{src="/images/2026/product_chatbot/product_chatbot_welcome_message_20260524.JPG" float="left" width="300" alt="Auntie welcome message" caption="Auntie welcome message"}
The first was the welcome message. In the earlier version, a generic message was generated by the LLM - something like `Hello! Welcome to our service. How can I assist you today?`. That added cost and told a first-time user nothing. I replaced it with a fixed standard message that describes what the bot can do.

::image{src="/images/2026/product_chatbot/conversation_memory_after.JPG" float="right" width="200" alt="With conversation memory" caption="With conversation memory"}
The second was conversation memory. Previously, each message was processed in isolation - the bot had no context from earlier in the session. It now feeds the latest N message pairs from session history into the LLM before generating a response.

The third was result relevance. Searching for 'sunflower oil' now returns more targeted results, though I am not fully convinced the improvement holds across all queries. 


<hr>

As I was fixing the initial issues, I discovered more.

::image{src="/images/2026/product_chatbot/search_loose.JPG" float="right" alt="Search with full text search" caption="Search with full text search"}

The first new fix was pagination. The chatbot now pages through results and lets users navigate back and forth before selecting a product.

The second was session state. Stale state from an earlier session could interfere with a new one even within the same five-minute window. The fix was simple: the bot resets session state whenever the user sends a greeting.

The third was search. The original SQL used `LIKE '%name%'`, which broke on multi-word queries like `pokka oolong tea`. I replaced it with full-text search using `tsvector` as the primary strategy, with trigram indexes as fallback.


<hr>

::image{src="/images/2026/product_chatbot/historical_prices_after.JPG" float="right" width="225" alt="New historical prices response" caption="New historical prices response"}

The historical pricing issue is not fully resolved. The error message is gone - it was caused by NULL type inference in a native query where the database expected a timestamp - but the response is still not useful for a question about price history. That work remains.

On top of missing supermarket coverage and an incomplete historical prices response, one more issue surfaced: duplicated entries in search results. The duplication causes confusion and is likely a data problem in the backend rather than a query issue.

I am taking a break soon, so the remaining issues will sit for a while. That is fine - the core flow works, and the next problems are clear enough to pick up when I return.
